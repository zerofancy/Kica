进入阅读前，选择是否继承进度

目标章节的阅读记录超过第一页时，先让用户选择“继续阅读”或“从头开始”；记录就在第一页时直接进入，不询问，也不在正文就绪前覆盖旧进度。

2026-11-16 · Kica Desktop / Android · 已按确认方案实施，验证记录见第 09 节

01 / 目标与范围

  • 每次从阅读器外部进入某章节时，先读取该章节的本地进度；仅当 pageIndex > 0 时询问。无记录或记录就在第一页（pageIndex = 0），均直接从第一页进入；已有记录时保留其阅读模式。
  • 两种选择明确且对等可达：继续原位置，或回到目标章节开头；支持取消本次进入。
  • 桌面与 Android、在线与已下载内容采用一致规则。
本版范围决策：“此前进度”指同一漫画、同一目标章节的记录；“从头开始”指该章节第一页，不是全书第一章。其他章节有记录，不改变用户此次选中的章节。

不增加“以后不再询问”、全局自动恢复开关、全书进度清空、跨设备同步、像素级滚动位置恢复或已读状态重设计。

02 / 现状与差异

当前阅读路由携带 comicId、episodeId；ReaderScreen 按这两个标识调用 LibraryRepository.readingProgress，读取完成后直接使用历史 pageIndex，并恢复 mode，没有用户选择步骤。

ReadingProgress 包含章节、从 0 开始的页索引、阅读模式与更新时间；不包含图片内滚动偏移。阅读布局通过 savePage 保存进度，并更新阅读历史。

阅读器内跨章已有显式落点：下一章开头、上一章末尾。本次仅改变外部进入时的恢复决策，不打断连续跨章，也不改变这些落点。

03 / 触发规则

场景行为
外部进入，目标章节无进度不询问，直接从第 1 页进入。
外部进入，目标章节记录在第 1 页不询问，直接从第 1 页进入，保留记录中的阅读模式；单页章节的末页也是第 1 页，同样不询问。
外部进入，目标章节记录超过第 1 页展示选择框；末页记录也询问，不推断“已读完”。按原始页索引判断，双页模式不能因第 2 页与第 1 页同组而跳过询问。
只有其他章节有进度不询问、不跳章；从当前目标章节第 1 页进入。
阅读器内上一章／下一章、边界跨章不询问，遵循既有跨章落点，不恢复目标章历史中间页。
重组、窗口调整、切换阅读模式、加载重试不重复询问，不清除当前会话的已选结果。
切到后台再回到同一阅读会话不重新询问。页面真正退出后再次进入，则重新检查，仍按“超过第一页才询问”的规则处理。
进程重启后重新打开阅读路由作为新进入处理；仅记录超过第一页时再次询问，不沿用上个进程中的临时选择。

所有已有及后续外部阅读入口统一经过同一入口门控，不在各入口各自弹框。若未来添加“继续阅读”入口，按钮名称本身也不视为本次二选一确认。

04 / 对话框与操作

继续上次阅读？

你上次读到「第 12 话」第 8 页。
继续上次的位置，还是从本章开头开始？

取消 从头开始 继续阅读

以上为静态示意，不是可操作原型。章节名与页码动态填充；显示页码 = pageIndex + 1。尚无可靠总页数时只显示“第 N 页”，不显示猜测的百分比或总页数。

  • 继续阅读：采用读取到的目标章节页索引与历史阅读模式；纵向从该图片起始位置显示，双页定位到包含该原始页的分组。
  • 从头开始：目标章节原始页索引设为 0。仍沿用该章节记录的阅读模式，不将位置重置扩展为重置模式或其他阅读偏好。
  • 取消：放弃此次进入，回到发起阅读的原页面，保留其筛选、滚动位置和导航上下文；没有上级页面时回到应用默认主页面，不退出应用。
  • “继续阅读”为主要操作；“从头开始”不能用低对比度隐藏。桌面初始焦点放在“继续阅读”；Tab / Shift+Tab 遍历，Enter / Space 仅激活当前聚焦按钮。
  • Android 系统返回键／返回手势、桌面 Esc、点击遮罩均等同“取消”；使用 PlatformBackHandler 统一返回回调，一次操作不能同时关闭框并额外弹出一层页面。
  • 选择框展示时焦点限制在框内，底层不响应翻页、滚动、模式切换或快捷键；选择完成并进入阅读后，再将桌面焦点交给正文。
  • 小窗口、长章节名或大字体下允许内容滚动，操作按钮保持可达。桌面溢出区域必须配同状态、可见且可拖动的滚动条，仅可滚动时显示；移动端可触摸滚动。

按钮、标题、正文、错误及提示全部纳入现有字符串资源体系。辅助技术可读出章节与页码，长标题可换行，不仅依靠颜色区分操作。

05 / 进入流程与状态

  1. CheckingProgress：创建一次进入会话，冻结目标漫画／章节标识，读取本地进度；显示轻量加载态并允许返回。不挂载会产生进度回调的正文布局。
  2. AwaitingChoice：仅当存在记录且 pageIndex > 0 时，固定本次进度快照并展示选择框；无记录或 pageIndex ≤ 0 时直接将进入决策设为 Start（页 0），已有记录则保留其模式。负索引视为异常的第一页记录，不询问，并按异常规则提示修正。框下不短暂展示历史页或第一页。
  3. Resolved：原子接收一个 Continue 或 Start 决策；立即防止重复提交，准备目标章节页列表。允许预取数据，但不得在选择前产生阅读行为或历史写入。
  4. LoadingContent：等待非空页列表，校验落点；失败时保留选择，允许重试或返回，不再次询问。
  5. Reading：将模式和初始页一次性交给阅读布局；定位完成、正文实际可见后，启用正常进度／历史保存。
  6. Cancelled：结束进入会话，忽略所有迟到结果，返回原页面。不得保存本次候选位置。

选择状态按一次外部进入会话持有，不能只按 currentEpisodeId 触发弹框。跨章使用独立的显式导航原因及落点，不重新进入 AwaitingChoice。

即使页面框架已经进入阅读路由，决策完成前也只能显示门控层，不允许正文布局先启动、保存第 1 页后再读取或恢复旧进度。

06 / 保存语义与异常

  • 选择不是立即重置：点击“从头开始”本身不删记录、不清空历史；第 1 页成功定位并可见后，才按现有流程写入该章节新进度和历史。从头开始后正常阅读，最新位置成为下次询问时的进度。
  • 失败不损坏旧数据：选择后加载失败、空章节、加载中退出，均保留旧记录。继续阅读定位成功后，按正常阅读规则更新访问时间和历史。
  • 进度读取失败：不能当作“无记录”。显示“无法读取阅读进度”，提供“重试”“取消”，不自动从第一页进入并覆盖可能存在的记录。
  • 页索引越界：在非空页列表就绪后，将索引裁剪到 [0, 页数 − 1]；发生修正时提示“章节页数已变化，已定位到可用页面”。负索引也按此处理；空章节不执行裁剪或保存。
  • 目标章节失效：显示不可用／加载失败状态，提供重试和返回；不静默跳到其他章节。
  • 离线：进度仍从本地读取；内容沿用现有下载回退机制。内容不可用时遵循失败不写入规则，不新增离线进度副本。
  • 异步竞态：读取、加载、定位与保存回调都绑定进入会话及章节；返回、切换目标或卸载后，旧任务不能弹出框、抢焦点或覆盖新会话进度。相同章节写入按顺序提交，避免旧写入晚于新落点覆盖。

恢复精度保持现有原始页粒度；双页归组和模式切换遵循现有逻辑。无需新增数据库字段，也不修改 FileProvider 或文件共享权限。

07 / 实现落点（Review 通过后）

  1. 在 ReaderScreen 前置统一进入门控，或拆分为入口容器与正文；抽出小型可测试状态机，区分外部进入和会话内跨章。
  2. 复用 LibraryRepository.readingProgress 与 ReadingProgress；去除外部进入路径中“读取完成即自动恢复”的隐式行为，让初始模式与页索引由已确认决策统一提供。
  3. 为正文挂载、初始定位和 savePage 建立就绪门槛，防止初始 0 页回调抢先写入；不改变正常滚动、分页及阅读历史的业务含义。
  4. 新增可复用的进度选择框和读取错误态，落实 Android 返回、桌面 Esc、焦点隔离、滚动条与本地化。
  5. 添加状态机及仓库交互测试，补充桌面真实窗口和 Android 返回流程回归。新增文件按职责拆分，每个默认不超过 500 行。

主要涉及 ReaderScreens.kt、必要的入口状态／对话框新文件、现有 ReaderLayouts.kt 的初始定位与保存协作、字符串资源及对应测试。路由无需因本需求必然新增字段。

09 / 实施与验证记录

  • 统一入口门控、选择框、错误重试与会话内恢复已实现。页 0 不询问，跨章不读取历史落点；加载中的目标章与模式选择保留在会话内存，不提前写入仓库。
  • 进度和历史由会话内单一 FIFO 消费者依序保存；旧布局、过期读取与卸载后的回调不再提交候选位置。
  • 新增 12 项状态机／落点单元测试、3 项保存队列测试与 6 项真实桌面窗口测试。新增窗口用例已通过，覆盖五种模式下继续／从头、页 0 免框、三种取消方式、空页／失败不写入、锁屏重挂及加载中跨章重挂、小窗口长标题。
  • 共享桌面代码与 Android 代码编译通过；完整桌面测试任务通过（80 项中 75 项通过、5 项无关窗口测试因未启用各自 opt-in 而跳过），阅读器新增窗口测试及既有五种模式键盘回归均实际执行通过。旧键盘用例的工具栏像素采样改为相对窗口内容区，避免窗口装饰高度不同造成误判。
  • 桌面窗口测试在隔离 X11 显示中运行，使用软件渲染，并通过测试 JVM 的 -Dskiko.vsync.enabled=false 避免虚拟显示的帧限速停滞。此参数仅用于测试，不修改产品默认渲染配置。
  • 验证缺口：没有连接 Android 设备，未实机验证界面返回、系统返回键与返回手势。大字体与桌面滚动条拖动仍需专项人工验收；小窗口滚动条已确认可见、键盘操作可达。
