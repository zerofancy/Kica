SPEC · v1.1 · 全量实现完成 · 本轮回归通过

Decompose 全量导航与状态保留迁移

一个版本内完成 Android / Desktop 全部应用内页面的组件化、独立栏目栈、状态保留、返回分发及恢复接线；不以只迁移导航壳或保留长期双轨实现作为完成。

2026-11-22 · 技术路线及状态规则已由用户选定 · 实际测试结果与未验范围见实施与验证记录，本文仍作为行为验收规格。

范围状态规则组件架构页面清单返回恢复迁移清理验收

01 / 决策、范围与完成定义

规范优先级：本文取代前期对比方案中“优先试点 Navigation 3、逐步选择路线”的建议。正式路线为 Decompose；工程内部可分步实现，但必须一次完整交付，不能以试点通过代替全量完成。
  • MUST：迁移六个主栏目 Home、Discover、Favorites、History、Downloads、Settings，以及 RandomComics、Search、Detail、Reader；包含登录、恢复中、锁屏覆盖和主会话边界。
  • MUST：页面业务状态、加载任务、输入/筛选/分页、滚动、阅读器状态及跨页面局部更新纳入明确所有权；Android 与 Desktop 使用同一导航语义。
  • MUST：Android AI 操作选项继续采用独立 AiOperationOptionsActivity。SAEP 协议仅接受以 Activity 为单位设置策略，因此不得将此入口合并到 MainActivity 的 Decompose 页面、弹窗或栏目栈。Decompose 仅可用于该独立 Activity 内部的状态管理，不替代 Activity 安全边界；系统文件选择器、权限框仍归平台管理。
  • MUST NOT：迁移结束后仍由旧 backStack、根级 SearchPageState / ReaderSessionMemory 状态表决定业务页面存活，或双写两套导航状态。
  • 不在本次：Web/iOS、桌面退出后恢复整栈、深链接新能力、双栏导航新布局、预测返回交互动画、MVIKotlin/新 DI 框架、发布软件包、账户数据库重设计。
  • 既有阅读进度、标签交互、桌面快捷键、下载、翻译、锁屏和文件共享安全不得退化；允许为组件化重构内部实现，不改变已有业务含义。

迁移前现状见前期调研；迁移后实现入口为RootComponent与MainComponent，保留AppRoute作为目的地 DTO，不再作为页面唯一身份。

02 / 状态保留契约

核心原则：页面仍在组件树/栏目栈内，保留业务状态与 UI 恢复状态；页面真正出栈就释放。页面级别和路由参数相同与否，不决定保留。

ID / 操作必须发生不能发生
R01 · 列表 → 详情 → 返回原列表结果、已加载页、筛选、输入和滚动锚点恢复。重置第一页、重新初始加载、成功内容闪回整页 Loading。
R02 · 详情 → 阅读器 → 返回恢复同一详情组件；定向更新阅读进度。无故重取全部详情/章节、丢详情位置。
R03 · 栏目 A → B → A恢复 A 的完整子栈与各页状态；再次点击当前栏目无副作用。隐式清栈、回栏目根页或刷新。
R04 · 弹窗、抽屉、菜单只影响临时交互；关闭不重建底层页。关闭弹层同时 pop 页面。
R05 · 锁屏、切后台、布局变化同进程下保留导航与业务对象；解锁不重复进入阅读进度选择。锁屏当作登出、重建页面组件；横竖屏/窗口宽度作为组件 key。
R06 · pop 当前页当前页销毁，恢复下层；重开相同参数是新 entry。从历史页面对象表复活已出栈页面的临时状态。
R07 · 显式刷新/改变查询保留组件身份，按请求策略重置相关数据。连带清理无关栏目或其他页面。
R08 · 登出/换账号释放旧 Main 树、内存数据投影与任务，拒绝旧异步结果。旧账号页面或结果进入新会话。
R09 · Android 配置重建通过 InstanceKeeper 保留业务 store；重新绑定新 UI/平台句柄。保留 Activity/Window/FocusRequester，或误当成普通冷启动。
R10 · 系统进程回收后恢复恢复有效导航及小型快照；按需重建数据，允许必要请求。承诺内存对象复活、完整分页数据放入 Bundle。

“不刷新”指纯导航事件不触发页面主数据重载，不禁止本地 Flow 更新、明确的业务修改或已有屏蔽规则触发的必要元数据核验。验收时必须区分这些请求来源。

03 / 组件树与导航所有权

平台宿主（Android Activity / Desktop Window）
└── RootComponent：启动恢复、认证、会话 epoch、锁屏控制
    ├── Restoring / Login（互斥，不是主栈历史）
    └── MainComponent（每个已认证会话一个）
        ├── SessionData：随机推荐共享数据、实体局部变更投影
        └── ChildPages<SectionConfig, SectionComponent>：仅含已访问栏目
            ├── Home       ── ChildStack<PageConfig, PageChild>
            ├── Discover   ── ChildStack<PageConfig, PageChild>
            ├── Favorites  ── ChildStack<PageConfig, PageChild>
            ├── History    ── ChildStack<PageConfig, PageChild>
            ├── Downloads  ── ChildStack<PageConfig, PageChild>
            └── Settings   ── ChildStack<PageConfig, PageChild>
独立 Android AI Activity ── AiOperationOptionsComponent（不共享主栈）

3.1 栏目容器：明确禁止默认销毁策略

  • Main 使用 PagesNavigation + childPages；初始仅 Home，首次选择新栏目时追加并选中；栏目顺序用稳定 SectionId 定位，不以可变数组下标当身份。
  • pageStatus 必须显式指定：选中栏目 RESUMED，其他已访问栏目 CREATED；父生命周期进一步限制实际状态。禁止使用默认“相邻保留、远端 DESTROYED”的行为。
  • 每个 Section 只有一个非空 ChildStack，根页固定；其栈顶随栏目活跃，非栈顶停止但保留。未访问栏目不创建组件、不请求数据。
  • 首次加载由业务 store 第一次活跃时的幂等 ensureLoaded() 触发，不在组件工厂或反序列化期间立即为全栈发请求。
  • UI 只渲染选中栏目，不引入可滑动栏目分页器；栏目变化通过 sidebar 操作提交命令。
  • 已访问但不活跃的栏目，其 UI 可退出组合；UI 保存必须另行接线，不能把组件没销毁误当作普通 remember 没销毁。

3.2 PageConfig、EntryId 与命令

  • 采用可序列化 PageConfig(entryId, destination)；Destination 为封闭类型，覆盖全部既有路由。entryId 在一次新进入时生成，保存/恢复沿用，不能由路由 toString、漫画 ID、Compose 调用次数或当前索引推导。
  • 相同参数允许出现多个 entry：详情 A → 标签搜索 → 详情 A 不冲突；同一漫画的不同 entry UI 状态独立，实体修改共享。
  • selectSection(id) 只切换栏目；open(destination) 在当前栏目 push；back() 按第 06 节；logout() 替换认证边界。命令主线程串行处理。
  • 快速连点同一个可导航控件只提交一次进入意图；禁止用“栈中存在该业务 ID”全局去重，避免破坏合法重复 entry。
  • AppRoute 如保留，仅可作为无状态业务目的地或适配 DTO；不得再充当唯一页面身份和第二份导航容器。
  • Children/ChildPages 的 key、StateKeeper key、InstanceKeeper key 必须在父作用域内唯一且恢复稳定；不启用全局 duplicateConfigurations 开关规避身份设计。

3.3 Component / Store / UI 边界

Component 暴露只读 StateFlow<UiState> 和事件方法；业务 store 实现 InstanceKeeper.Instance，并负责分页、任务、generation 与清理。StateKeeper 仅保存可恢复的小型 Snapshot。UI 接收 component/state，不再拿 Repository 发页面主数据请求。

允许 UI 保留焦点、动画、手势、布局测量、与真实可见性绑定的预加载及其 effect；所有需要跨页面离屏保留的业务状态必须移出普通 remember。错误保存为可解释的数据，文案由 UI 资源层渲染，避免语言/主题变化重建 store。

InstanceKeeper 中的 store、SessionData 和写入协调器不能捕获可重建的组件外壳或其导航 lambda；组件重建后重新绑定输出/平台回调并注销旧绑定。纯业务状态可保留，导航与原生句柄必须指向当前宿主。

所有列表保留未按屏蔽规则破坏性裁剪的原始结果，规则变化重新计算投影，不重新拉整份列表；未知标签核验仍复用既有解析/缓存逻辑。标题翻译保留应用级服务，只在 UI 可见时做必要订阅，不因页面返回重启模型。

业务确认对话框的临时输入可在当前显示期间存在，但通用菜单、帮助框、toast、焦点对象、按钮 pressed 状态不作为跨离屏恢复契约。离开栏目、锁屏或 UI 重建时关闭这些临时交互；业务入口选择不是普通临时菜单，按下一节处理。

05 / 阅读器专项：不得因迁移改写阅读语义

兼容既有阅读进度选择 spec与桌面阅读器键盘 spec；本次只改变所有权与生命周期。

  • 新 Reader entry 只读取所选目标章节进度；超过第一页才询问，第一页/无记录直接就绪；“从头开始”只指该章节，保留既有模式规则。
  • 同一 entry 的 Checking / Failed / Choice / Ready 为组件状态；普通离屏、锁屏、配置重建后不重复询问已确认选择。Choice 尚未确认时恢复同一选择流程，不擅自继续。
  • 进程重建：已 Ready 的 entry 从快照中的当前章节/实际页恢复，不当作外部新进入；未确认 entry 重新读取进度并展示必要选择。快照缺失则走新进入安全流程，不写入虚构进度。
  • 内部跨章不 push 新页面、不再次触发入口选择；下一章从开头、上一章从末尾，保持原行为。未完成跳转的目标和末尾意图在内存中保留，但不作为已读进度持久化。
  • 页列表按当前章节加载；同 entry 返回/解锁不重拉；新章节、显式重试才发请求。网络失败仍走已有 downloadedPages 离线回退，不误删下载任务。
  • 页面布局只有在真正显示有效页后才报告进度；报告携带 entryId、章节和 layoutGeneration，过期布局、模式切换前回调、取消进入、已销毁页面均不能写进度。
  • 进度和历史写入以会话级串行写入协调器承接，不再使用随组合销毁而取消的 writer。已接受的最后有效页应在 pop/锁屏/正常窗口关闭边界提交；按顺序写入，旧慢请求不得覆盖新进度。
  • 页面 pop 取消页面读任务，但不能取消已接收的有效进度写入；登出先停止新报告，再有界排空旧会话写入或明确记录失败，随后关闭会话。不能让旧写入通知新账号 UI，也不承诺强杀进程时未落盘队列不丢失。
  • 复制/保存图片的原生对话框使用当前宿主句柄；组件不能持有旧 Activity/Window。UI 重建后失效结果不再投递旧 entry，任务是否完成由平台结果确定。
  • Esc/键盘帮助/上下文菜单/章节跳转/按键去重、失焦释放保持；最小化、锁屏或离开阅读器时清 held keys 并停预加载，恢复不产生幽灵翻页。

当前迁移重点：ReaderEntrySession、ReaderContent 业务加载及进度回调、SessionProgressCoordinator（替代旧 ReaderProgressWriter）。可复用纯逻辑算法及测试，不保留旧根级会话 Map。

06 / 导航与返回：唯一分发链

  1. 平台原生模态交互先由平台消费；锁屏/认证边界不得放行业务导航返回。
  2. 普通业务 UI：关闭最后显示、可返回的菜单/弹窗/阅读器临时交互。
  3. 关闭展开的导航抽屉。
  4. 当前栏目栈深度大于 1：只 pop 一页。
  5. 当前栏目在根页且非 Home：选择 Home，恢复 Home 原有子栈，不隐式清除 Home 深层页面。
  6. Home 栈根页无临时交互：Android 不拦截系统默认退出；Desktop Esc 不关闭应用。

栏目选择历史不是回退栈；Home 根页返回不会重新跳到上次栏目。阅读器 UI 返回按钮与普通页面 UI 返回按钮调用同一 back 意图，阅读器未确认入口的取消逻辑先经入口状态机保证只出栈一次。

  • 继续使用项目 PlatformBackHandler 作为系统返回与 Esc 的平台适配。所有 ChildStack / ChildPages 禁止自动处理返回（handleBackButton=false），由活跃 Main/Section 的统一 back 方法执行命令。
  • 页面临时交互可保留局部 PlatformBackHandler，但只能登记当前可见最上层交互；不能同时调用 pop，不能由隐藏栏目拦截；返回消费优先级必须测试而非仅依赖假定的注册顺序。
  • UI 与主树之间保持单一事件路径；系统一次返回、单次 Esc 按下最多消费一层，长按/键重复保持已有去重。
  • 锁屏默认消费返回且只停留在锁屏，不修改底层栈；锁屏控制层限制 Main 生命周期/可交互状态，解锁仅恢复，不能靠移除 Main 组件实现。
  • 阅读器全屏通过同一个 section/entry 渲染宿主决定壳层可见性；不要因读者全屏把 Children 放入另一棵组合子树而丢失原保存域。

07 / 请求、跨页面更新与任务生命周期

7.1 请求状态机

  • ensureLoaded()：未加载且无运行中任务才启动；已有 Data/Error 不因 resumed 重试；Error 由用户重试或明确业务事件处理。读到缓存后只在初始加载周期内做一次必要远程校验。
  • 普通 push/pop、切栏目、恢复组合、解锁和 resumed 均不是 refresh。此次不引入 TTL 自动返回刷新。
  • 刷新可替换第一页、重置分页；有旧数据时维持内容与独立 refreshing/error，不先清屏。新查询成功后定位顶部；显式刷新成功后允许定位顶部，失败保留原结果与位置。
  • 分页同一页只允许一个请求；刷新/查询条件变化增加 generation，取消或忽略旧请求；必须在完成、取消、失败路径清理 busy，避免永久 loadingMore。
  • 捕获异常必须重新抛出 CancellationException；禁止把取消转换成用户错误、离线回退或缓存写入成功。

7.2 局部数据一致性

新增会话级 SessionData，用可重放的状态投影/版本号承接按漫画 ID 的已确认收藏、点赞、进度和标签变更，不能只用离屏期间会丢事件的无重放一次性事件流。它不替代持久化 Repository，也不是第二个导航状态表。

  • 收藏/点赞：操作成功后同步更新同漫画各详情 entry；失败回滚对应乐观修改，不能用旧请求覆盖新已确认结果。
  • 收藏集合：取消已存在漫画直接移除；新增但位置未知时标记集合 dirty，下一次可见只做一次有原因的静默集合校验，合并/去重并保持可用锚点，不闪回全页 Loading。属于业务变更请求，不是纯返回请求。
  • 历史/下载/设置：可暂停不活跃页的持续收集，但保留最近值；重新可见接收最新数据，不先置为空。不活跃页遗漏的实体变化通过版本投影补齐。
  • 屏蔽规则与翻译设置沿用已有语义，重新计算可见投影而非破坏原始列表。标签补查与操作请求独立计数，避免误判为页面主数据重载。

同栈后台 / 非选中栏目 / 锁屏已发起的有限数据请求或业务提交完成，结果写回保留 store。UI 键盘输入、持续预加载、新的可见性驱动补查；不从工厂批量拉取隐藏页。
entry 销毁已接受的进度/持久化写入交给会话协调器完成。取消页面任务、解除订阅/回调，拒绝页面新状态写入。
会话失效 / 宿主最终关闭有界收尾应用服务与已接受写入。销毁会话树/instance stores；清旧投影；禁止跨会话结果投递。

组件/store 通过构造器注入仓库；平台动作通过可重新绑定的 facade/事件接线，不捕获 Activity、Window、View、FocusRequester。所有导航和状态提交在主线程执行，IO 在适当 dispatcher；工作线程不能直接驱动 Decompose 导航。

08 / UI 保存、重建、认证与平台宿主

8.1 UI 保存边界

  • 栏目宿主建立以 SectionId 为 key 的 saveable 保存域，栏目内使用 Decompose 稳定版 Children；entry 以 entryId 绑定恢复。即使栏目 UI 整体离开组合，也要保留其 saveable 域。
  • 普通 remember 的状态必须逐项审计：应保留的改为组件状态或 rememberSaveable + 显式 Saver；敏感输入和临时焦点仍不保存。page 销毁立即清其保存域，session 销毁清栏目域。
  • 列表/网格保存稳定 itemId + offset 和必要 index fallback；规则更新、条目删除或列数变化后选择最近有效锚点。内容未就绪前不执行一次性恢复，避免空列表先消费锚点。
  • 离屏/重组不重复强制 scrollTo；数据稳定后只应用一次待恢复锚点。返回后的同布局应保持位置，跨布局不承诺同像素位置。
  • 桌面所有改动的可滚动区域必须保留可见可拖动滚动条，并绑定同一滚动状态；仅实际溢出时显示。

8.2 StateKeeper 恢复格式

使用版本化 NavigationSnapshotV1 / 各页小型 Snapshot，保存已访问栏目、选中栏目、entryId/目的地参数、输入/已提交条件、滚动锚点和阅读位置。选择一个真实恢复来源，不能同时从多份 JSON/Compose 状态表恢复同一业务字段。

  • 禁止保存完整网络结果、Bitmap、页图 URL 列表、服务对象、原生句柄、token、密码、锁图案。业务草稿与查询属于用户隐私，不输出到日志/诊断明文。
  • 恢复后仅首次活跃页按需加载；分页页范围只是恢复提示，逐页重建至锚点可定位或服务端末页，不把恢复数字当作已加载结果；失败保留待恢复锚点供显式重试，期间允许取消/返回。
  • 已在内存的普通返回保留全部分页，不走上述重建流程。未激活的栈中页不为“恢复滚动位置”后台批量请求。
  • 业务快照设置 256 KiB 编码预算并测试；超限先剔除可选草稿/次要 UI 保存信息，不在运行中销毁栈。必要导航仍超预算或格式损坏时放弃该恢复快照，安全回 Home，并保留持久化阅读记录；禁止静默恢复到其他账号。
  • 总 Android saved state 还包含框架保存域，须在深栈/长输入压力用例验证，不能以业务快照小于预算替代实际宿主恢复测试。
  • 当前无持久导航格式，首次升级冷启动无需复活旧内存栈；未来未知 schema 版本按安全回 Home 处理，不崩溃。

8.3 Android

  • Activity 在 onCreate 创建接入 Activity saved state / lifecycle / instance retention 的根 ComponentContext；使用非整体 retained root + InstanceKeeper store 方案，UI 观察新组件外壳而复用业务 store。不要再在 KicaApp 内 remember 根树作为全部接线。
  • 配置变更不销毁业务 store；最终 finish/entry pop 才清理相关实例。ActivityResult、文件树选择、权限和安全窗口 flag 沿用现有宿主职责，新 Activity 重新绑定 facade。
  • Root 初始为 Restoring，restoreSession 每个宿主会话只执行一次；认证未决不展示旧 Main/敏感内容。验证会话后才接入匹配的导航恢复，不匹配则丢弃旧 Main 快照。
  • 恢复边界包含不承载凭据的账户标识及登录会话标记；同账号显式重新登录也是新会话，不能仅凭 email 相等复活旧栈。会话标记由认证层维护，登出失效，token 不进快照。
  • 每次宿主冷恢复，按现有设置初始化应用锁，不能从 saved state 恢复“已解锁”绕过安全；已存在会话的配置重建不重复执行网络恢复。

8.4 Desktop 与独立 AI Activity

Desktop 在 UI 主线程建立根上下文，生命周期跟随真实窗口最小化、恢复和最终关闭；以官方 LifecycleController 或等效接线实现，正常关闭先有界收尾再销毁 root，不另开服务器或窗口替代现有应用。仅保存运行期栏目/页面，不新增磁盘全栈恢复。

AI 操作选项 Activity 创建自己的上下文/store/saveable 域，重建保留状态，finish 释放；设置写入与 SAEP 策略更新通过新宿主回调绑定。必须保留独立 Activity 的声明、平台启动入口及 SAEP 对该 Activity 的策略识别；返回由 Activity finish 回到原主界面，不操作主栏目栈。验收须确认策略仍以 Activity 为单位生效，且该页禁止 Agent 操作、不受主页面策略放开影响。不得复用 Main 实例、扩大 Agent 权限或改变安全策略。

8.5 内存边界

运行期不自动淘汰仍在栈内的页面业务状态，避免违反已确认规则；栏目惰性创建，图片交给图片库缓存，不由每页持有 Bitmap。pop/logout 必须释放 store、任务和 UI 保存域。压力测试记录深栈占用与释放后趋势；若需要栈深上限/淘汰，须另做产品决策，不能暗中削弱保留契约。
