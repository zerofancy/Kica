桌面阅读器键盘操作

打开漫画后即可用键盘连续阅读，覆盖滚动、翻页、跨章、工具栏与返回，并与现有鼠标操作共用阅读状态。

2026-10-17 · Kica Desktop · 本轮仅设计，尚未实施

01 / 目标与范围

桌面端进入阅读器后，无需先点击图片即可使用键盘。覆盖纵向、单页从左到右、单页从右到左、双页从左到右、双页从右到左五种模式，以及在线和已下载内容。

  • 用方向键、Page Up / Page Down、空格完成主要阅读操作。
  • 通过明确的边界规则跨章节；支持直接跳到当前章节首尾与上一章／下一章。
  • 工具栏、菜单和帮助均可通过键盘使用，焦点可见、返回顺序一致。

本期不增加快捷键自定义、键盘缩放／拖动画面、页码输入框、操作系统级窗口全屏或新的阅读模式。已有模式及适配按钮通过 Tab 与 Enter 操作。Android 不新增阅读快捷键。

02 / 现状与设计依据

当前 ReaderScreens.kt 中，纵向阅读使用 LazyColumn，单页与双页使用 HorizontalPager；双页按原始页序每两页分组，奇数尾页独立显示。已有滚轮／触摸跨章、阅读进度保存、图片右键菜单，以及桌面滚动条。

当前没有专门定义阅读快捷键；Esc 已经通过 PlatformBackHandler 处理图片菜单与页面返回。工具栏中名为“全屏”的按钮实际只隐藏工具栏，因此本期按键只切换工具栏显示状态，不改变系统窗口模式。

“下一页／下一组”始终指章节数据中的后续内容。左右方向键随阅读方向变化；Page Down 与空格始终向后阅读，不随左右模式变化。

03 / 默认按键映射

除明确列出的 Shift、Ctrl 组合外，以下阅读按键仅在没有 Ctrl、Alt、Meta 修饰键时生效。未列出的组合保留给系统或当前控件。Mac 的显式跨章同样使用 Control，不额外占用 Command 组合。

按键纵向阅读单页／双页阅读
↓ / ↑向下／向上滚动 64 dp下一页（组）／上一页（组）
→ / ←不绑定阅读动作从左到右：右下一、左上一；从右到左：左下一、右上一
Page Down / Page Up向下／向上滚动正文视口高度的 90%下一页（组）／上一页（组）
Space / Shift + Space同 Page Down / Page Up下一页（组）／上一页（组）
Home / End当前章节最顶部／最底部当前章节第一页（组）／最后一页（组）
Ctrl + Page Down直接进入下一章第一屏
Ctrl + Page Up直接进入上一章最后一屏，保持与现有向前跨章行为一致
F显示／隐藏阅读工具栏；保持当前阅读位置
F1打开“键盘操作”帮助；帮助打开时再次按下不叠加窗口
Esc依次关闭最上层菜单／帮助 → 若工具栏隐藏则恢复工具栏 → 返回阅读器上一页面。一次按键只执行一步
Tab / Shift + Tab按视觉顺序正向／反向移动焦点，覆盖可用工具栏按钮、正文焦点区、恢复工具栏按钮等；不拦截成阅读命令
Enter / Space（按钮聚焦）执行当前按钮的默认操作，不同时翻页或滚动

双页模式每次移动一组，即通常两张图片；如 5 页章节按 [1,2] → [3,4] → [5] 移动。左右模式只影响方向映射，继续沿用现有分组和图片排列。

纵向视口高度取正文实际可见区域，扣除工具栏；滚动距离限制在合法范围。Home / End 在章内定位，不触发跨章。

04 / 章节边界与连续输入

  1. 先到边界，再跨章。一次滚动／翻页只能到达当前章的边界，不把剩余距离传入下一章。已在边界时，释放按键后再次向外按下，才跨章。
  2. 前进落在开头，后退落在末尾。下一章进入第一屏；上一章纵向落到实际最底部，分页落到最后一页／组。显式跨章键遵循同样规则，不恢复目标章的历史中间位置。
  3. 长按不连续翻章。纵向 ↑ / ↓ 可使用系统重复事件连续滚动，但重复事件只滚动、不跨章。其他命令每次物理按下只执行一次，忽略自动重复；Esc 长按也不能连续返回多层。
  4. 不累积陈旧输入。分页动画及章节切换进行时，不排队执行翻页／跨章命令。切章后，切章前已按住的按键必须释放才可再次触发命令。
  5. 明确首尾反馈。没有目标章节时停留原处，以轻量提示显示“已是第一章”或“已是最后一章”，沿用约 2 秒提示样式；同一次长按不重复提示。

章节顺序与目标沿用当前 episodes 数据和 onChangeChapter 逻辑。章节列表未就绪时禁用跨章，不误报为全书首尾。图片尚在加载但页列表已就绪时可正常导航；页列表加载中、失败或为空时禁用阅读定位与跨章键，保留 F、F1、Esc 和控件导航。

05 / 焦点与事件优先级

  • 首次进入：阅读器成为当前页面且窗口激活后，正文获得焦点。数据加载完成不反复抢焦点；若用户已 Tab 到按钮，焦点保留。
  • 正文拥有阅读按键：仅正文焦点区处理方向键、空格、Page Up / Down、Home / End、跨章组合。工具栏按钮、输入框及其他控件聚焦时，阅读按键让位给控件默认行为；点击正文可恢复阅读焦点。
  • 工具栏操作结束：Tab／Enter 操作保留按钮焦点，便于连续设置；鼠标选择模式／适配后恢复正文焦点。关闭菜单／帮助后恢复打开前焦点，原控件已隐藏时回到正文。
  • 临时交互优先：图片菜单、帮助、系统保存对话框、应用锁屏显示时，停用底层阅读快捷键。菜单可用 ↑ / ↓、Enter 和 Esc 操作；焦点困在帮助／菜单内部，不穿透到底层。
  • 阅读器级命令：无临时交互且当前焦点不是文本输入时，F 和 F1 在正文与工具栏内均生效。Esc 继续统一交给 PlatformBackHandler。
  • 切换与失焦：切模式后正文导航绑定新模式的状态；切章后正文恢复焦点。窗口失焦、最小化或阅读器卸载时停止接收命令并清空按住状态，其他页面和其他窗口不响应。
  • 一次输入一次动作：已处理事件必须消费；同一事件不能再触发控件默认滚动、分页器默认翻页或第二条回调。未处理事件继续传播。

焦点必须有清晰可见的边框或高亮；Tab 到被工具栏横向滚动隐藏的按钮时，自动将该按钮滚动至可见区域，并共用现有滚动状态。

06 / 帮助入口与兼容约束

桌面阅读工具栏增加“键盘操作”按钮，标注 F1；打开与 F1 相同的帮助面板。面板按当前阅读模式展示方向规则，并列出通用按键、跨章边界提示和“按钮聚焦时空格执行按钮”的说明。提供关闭按钮，支持 Esc，打开后将焦点置于面板内。

工具栏隐藏时仍可通过 F1 查看帮助；关闭后维持原来的工具栏显示状态。F 切换工具栏只改变正文视口，不主动跳到其他页，纵向尽量保持同一首个可见图片及其偏移，最终偏移按新视口合法范围裁剪。

  • 鼠标、触摸、键盘与滚动条必须共用同一 LazyListState／PagerState，保持翻页、预加载和进度保存一致；无需新增数据库字段。
  • 保留纵向正文与工具栏现有桌面滚动条；新增帮助若内容溢出，必须提供可见、可拖动且共用状态的垂直滚动条，仅实际可滚动时显示。分页器不增加普通滚动条。
  • 新增帮助入口仅桌面可见；Android 的工具栏、触摸阅读与系统返回行为保持兼容。若调整共享返回结构，必须同步验证 Android 返回优先级。
  • 帮助、提示、按钮名称纳入现有字符串资源体系；不硬编码到按键分发逻辑中。

07 / 实现落点（Review 通过后）

  1. 在阅读器内定义统一阅读命令及按键到命令的映射，分离平台按键处理与阅读动作，便于测试方向、修饰键和重复事件。
  2. 为 VerticalReader、PagedReader、DoubleReader 接入命令执行，直接驱动它们现有的滚动／分页状态。记录加载、动画、切章和边界状态，串行执行定位操作。
  3. 桌面按键监听限制在当前阅读器及所属窗口，处理焦点、按住状态及卸载清理；Android 使用无操作的平台实现或明确的桌面条件分支。
  4. 在 ReaderScreen 加入帮助入口、工具栏切换与统一返回层级。Esc 复用 PlatformBackHandler，不额外注册一套独立返回路径；同时防止一次长按反复弹栈。

08 / 验收标准

场景通过条件
进入与恢复从详情／历史进入后无需点击可阅读；异步加载不抢走已移动到工具栏的焦点；窗口切回后无残留按住状态。
五种模式逐一验证方向、Page Up / Down、空格及 Home / End；右到左模式的 ← 前进；双页 5 张图片严格按三组移动。
纵向滚动↑ / ↓ 为 64 dp，Page / Space 为正文视口 90%；调整窗口及工具栏后距离按新视口计算，滚动条同步。
边界与章节到边界后需松开再次按键才跨章；Ctrl + Page 可直接跨章；上一章落最末屏；首尾章无跳转并正确提示。
快速输入长按纵向键连续滚动且不自动跨章；分页长按只动一次；连续切章与慢加载时无排队跳过章节、重复保存错误章进度或越界。
焦点与控件Tab 遍历及焦点样式清晰；按钮 Space 只激活按钮；模式按钮可纯键盘操作；横向隐藏按钮聚焦后进入可见区域。
浮层与 Esc图片菜单／帮助打开时阅读按键无效；Esc 只关顶层；隐藏工具栏时先恢复工具栏，再次 Esc 才返回；长按 Esc 不连续退出多层。
工具栏与帮助F 显隐不主动跳页；F1 与按钮入口一致；帮助关闭后恢复焦点；小窗口下帮助滚动条可见且可拖动。
状态与隔离键盘、滚轮、拖动滚动条交替后位置一致；退出再进入进度正确；加载／失败／空章不执行阅读命令；非阅读页、锁屏和其他窗口不响应。
平台回归桌面实际窗口验证以上交互；Android 编译及阅读触摸、界面返回、系统返回回归通过。平台未实机验证的部分明确列为验证缺口。

自动化重点覆盖：命令映射（含 RTL、双页、修饰键）、边界／重复按键状态机、跨章落点、Esc 单次返回。实际桌面窗口验证焦点、事件消费、弹出交互和滚动条；纯逻辑测试不替代这些交互验证。

Review 重点：默认按键是否顺手；左右键是否跟随阅读方向；边界二次按键跨章；Esc 先恢复工具栏再返回。确认后按本 spec 进入开发。
